# 0.4.14 场景隔离与下载调度

排查“只有识别、没有搜索下载”时区分三件事：当前提交的业务场景、界面分组以及待执行阶段。资料补全批次只整理本地原件的暂存副本，不会凭空创建音源下载；旧任务保存的 identify 分组会在读取时纠正为独立的“本地资料补全”，原记录不重写。任务中心显示场景数量，搜索和下载不会被大量待整理条目埋到后面几页。

修复全局“存在任何活跃任务即拒绝新批次”的条件：已完成准备的资料补全与独立歌单可共存；同场景重复提交、并行索引准备、升级及缺曲补全与其他写库场景仍互斥。发布继续逐项执行并核对原件哈希。识别与搜索在两线程环境也保留位置；下载提交与进度轮询优先于大量资料整理，但三次后让资料整理获得机会，已验证的入库仍最高优先。

新增独立档案回归覆盖：跨场景接受、重复与替换批次拒绝、准备互斥、历史任务分组纠正、下载调度与公平性、双线程预留，以及缓存加载不联网、不自动勾选、不自动创建下载。实际冻结程序增加跨场景提交、历史分组与不完整缓存三项检查，Windows 与 macOS ARM 发行均执行；不下载真实音乐、不消耗 FL。部分歌单缓存保留原有完整性标记，不能将平台未返回的歌曲当成已识别歌曲。

# 0.4.13 有上限的并行任务

后台原先每次只执行一个专辑阶段，慢请求和整张专辑的流媒体回退会拖住其他任务。现在由一个协调任务原子领取最多 4 项独立识别、检索或流媒体阶段；流媒体和暂存副本资料整理分别最多 2 项，写库阶段保留独占调度。线程沿用进程的小核与后台优先级；未识别到小核时由系统分配。

| 并发风险 | 处理与验证 |
| --- | --- |
| 重复领取、依赖未完成就开始 | 锁内领取并保存运行状态；选择器仍检查父任务、暂停、隐藏与下次轮询时间；合成 8 项任务分两波各执行一次 |
| FL 重复消费、入库冲突 | 令牌下载、qBittorrent 提交、元数据与发布事务保留独占阶段；流媒体使用独立任务目录，旧路径迁移串行 |
| 站点并发过高 | 每站检索锁覆盖完整关键词尝试，跨站可交错，同站等待可取消；目录接口沿用各源速率限制 |
| 线程失去暂停取消上下文 | 传递协调任务 ID 并在结束恢复线程上下文；执行前重新检查暂停与取消，协调器等待全部线程再完成任务 |
| 共享连接初始化竞争 | 目录和 PT 客户端缓存构造加锁，HTTP 连接池初始化加锁；已创建连接可复用 |
| 个别阶段失败拖掉整波 | 每项沿用持久化错误处理，失败隔离；合成测试检查其他任务完成、无遗留 running 项 |

新增并发回归使用独立临时档案、合成阶段和站点响应，覆盖并发上限、流媒体双任务、同站互斥、父依赖和轮询限制、暂停、失败隔离及安全退出守卫。此类测试不代表真实站点下载速度，不下载真实音乐、不消耗 FL 令牌。Windows 冻结程序和 macOS ARM 原生安装验收由发行流程保存证据。

# 0.4.12 PT 检索与回退修复

本轮针对“任务集中显示流媒体完整音源回退”追踪历史检查点、真实检索返回、候选匹配与调度。旧保存异常恢复的回退检查点曾直接继续下载，跳过后来改进的检索；合作艺人长关键词无结果后也可能漏掉专辑名检索。站点本身能返回候选，候选艺人和发行歧义与没有资源必须分开。

| 修复 | 验证 |
| --- | --- |
| 旧恢复任务按当前配置重新检索一次，保留原检查点缓存与收据 | 合成任务验证缓存不变、当前启用站点生效、关闭回退设置生效，以及已重检任务不循环 |

另在本机用已有登录状态进行了三站只读检索：均能返回候选，合作艺人长关键词与主艺人关键词返回不同，证明存在关键词漏检。私人歌单、候选和凭据记录不入仓库。本次验收不下载真实音乐、不消耗 FL 令牌；找到同名候选不等于已确认艺人、录音或特殊发行。

# 0.4.7 代码审阅与验证

本次检查覆盖应用、打包脚本和测试代码。对应用 Python 模块逐个完成语法、导入和结构检查，并沿着歌单、识别、搜索、下载、整理、入库、恢复和更新的调用路径审阅状态与数据交接。测试覆盖正常流程、异常、取消、并发、旧数据和重启恢复。

## 各模块的检查重点

| 模块 | 检查内容 |
| --- | --- |
| `app` | 阶段依赖、队列公平性、AI 核对、失败重试、暂停取消、旧配置快照与记录删除 |
| `worker`、`state` | 并发 IPC、请求编号防重、SQLite 事务和连接清理、查询索引、单后台写入 |
| `providers`、`clients` | 歌单完整性、四站结果区分、Cookie 域绑定、FL 令牌与个人免费、下载前 qBittorrent 检查、超时和验证服务 |
| `domain`、`library`、`media` | 发行和曲目身份、音质比较、增量索引、时长及完整解码、NCM、标签、封面、歌词、文件事务和恢复 |
| `gui` | 当前专辑和历史阶段的区分、筛选分页、全队列搜索、勾选和批量操作、回调结束、设置和凭据显示 |
| 更新及打包 | 同一提交构建、安装升级、档案保留、Windows 版本、macOS ARM PKG、附件完整性和 SHA 校验 |

## 发现并处理的问题

| 问题 | 调整 |
| --- | --- |
| 旧识别、搜索积压压住新生成的下载任务 | 优先推进下载、整理、验证和入库，保留父阶段、暂停及轮询时间约束 |
| 已完成的前置阶段挤满列表，容易误认为已入库 | 默认专辑总览展示当前阶段，阶段记录保留历史；删除后续任务后不重新显示前置记录 |
| 历史任务缺少新增的流媒体设置 | 执行时补齐配置缺省值，保留任务原有目录和凭据引用；失败任务仍由用户明确重试 |
| 连接测试排在音乐队列后面 | 独立执行 FlareSolverr 和 qBittorrent 连接测试，显示耗时、结果或失败原因 |
| AI 排队文字遮盖真正的连接错误 | 同时展示实际阻塞原因和 AI 辅助状态 |
| AI 完成写回与删除、取消、暂停竞争 | 在同一互斥范围读取最新任务并写回辅助状态，避免旧快照覆盖用户操作 |
| 内置引擎共用启动锁 | 每个引擎独立串行启动，关闭时按固定顺序取得全部启动锁；启动检查响应后台退出；音乐任务在释放启动锁后再等待暂停恢复 |
| 已在运行的工作流仍可能再次进入调度选择 | 排除已经保留执行权的 `running` 阶段 |
| SQLite 初始化异常可能遗留连接，AI 队列查询反复扫描 | 确保初始化异常也关闭连接；WAL 在数据库初始化时设置；增加 AI 队列专用索引 |
| 批量按钮常驻、当前操作与状态不符 | 勾选后显示批量操作；根据当前阶段启用核对和重试；切换视图清空勾选，翻页保留 |
| 主界面出现独立验证服务入口 | FlareSolverr 全部放入连接与设置，设置首页提供直达按钮 |
| 标签计划使用可变缺省参数 | 改为不可变的空元组，明确锁定字段的只读用途 |

NCM 合成样本测试会先验证样本哈希，再复制到普通临时目录解密，因此工作区经过 Windows 目录联接时也能验证解密结果。实际程序继续拒绝未经确认的 junction、symlink 和 reparse 路径。

## 验证层次

1. **源代码回归**：执行完整测试集，重点包含真实格式的合成音频、FL 未知结果防重、文件事务、取消恢复、并发删除、队列调度和界面交互。
2. **Windows 实际程序**：验证冻结后的 EXE、并发连接、三类流程入口、后台暂停时的独立连接测试、内置服务、真实本机浏览器和完整安装升级。
3. **macOS 原生环境**：GitHub Actions 在 Apple Silicon 环境验证 Keychain、Unix IPC、文件锁、实际应用、PKG 安装、重复安装和档案保留。
4. **发布附件**：核对版本、源码提交、构建清单、全部附件和 SHA-256 / SHA-512；同步敏感信息扫描，保留历史 Intel 附件。

验收使用隔离档案和合成资料，不为测试启动真实音乐下载、消费私人站点 FL，或删除原音乐。真实下载还依赖账号权限、站点可用性、qBittorrent WebUI 和播放器授权。源代码测试、合成入库和真实站点验收的证据分别记录，不把连接成功视为真实音乐已经入库。

Release 中的构建清单记录对应源码提交与原生验收结果；失败或缺少平台产物时，完整发布流程会停止。测试通过不能证明不存在其他问题，仍可通过 Issue 提供脱敏错误信息和复现步骤。

## 0.4.8 增量检查

## 0.4.9 增量检查

审阅范围覆盖歌曲及专辑去重、事务恢复、分页与切页绘制、后台核心和线程策略、库旁下载目录、做种迁移、资源补全及旧任务恢复。歌曲重复以完整字节或保持采样精度的完整 PCM 内容为证据；发行合并需要发行 ID 和曲目表，声道、版本、CUE、歌词、封面或字段锁冲突保留核对。合并和恢复只能访问本次检查过的音乐库文件，不能把下载目录当作重复副本删除。

下载入库通过完整解码、身份和文件哈希检查后，才清理有清单记录的临时文件。qBittorrent 迁移使用持久化意图，限制创建记录、哈希、分类、路径与自动管理状态，核对迁移后字节和客户端实际位置；请求超时后先对账，不重新加种。旧版流媒体缓存随任务迁移到库旁目录，修复网易云自引用造成的任务 JSON 保存异常。已验证的发布优先于搜索和回退任务；发布重试复用已经存在的事务，长名称预留原子提交临时文件空间。

封面检查包括本地资源、精确专辑 API、已确认发行封面及官方歌曲对应专辑 ID。合辑曲目艺人与发行艺人的差异不能把已确认专辑 ID 错判为不匹配。未知艺人和编码替换字符视作缺失身份，不能作为已识别资料发布。歌词保留同名同步 `.lrc`，同时补写入库副本的歌词标签；Roon 的标签导入支持以[官方说明](https://help.roonlabs.com/portal/en/kb/articles/lyrics)为准，文件存在不等于播放器显示验收通过。

回归使用合成音频覆盖逐字节/PCM 去重、不同精度与声道、分散发行、冲突拒绝、字段与资源变更、恢复、迁移中断、临时副本清理、官方歌词兜底、内嵌歌词、长 Unicode 名称和重复发布。实际打包进程另验入库后的标签、封面、旁置歌词、临时文件清理和正常退出。Windows 小核策略通过本程序自己的子进程验证；Mac 核心调度交给系统。原生安装、Mac Keychain 和 Apple Silicon PKG 安装升级继续由完整发布工作流验证，公开清单以该提交对应 CI 结果为准。
