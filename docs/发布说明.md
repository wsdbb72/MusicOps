MusicOps 0.4.34：0.4.33 的干净重发（tag、资产、Docker latest 三者一致）+ 补齐设置入口。

本版取代 0.4.33：0.4.33 的 tag 指向的是有 bug 的旧代码，而 Release 里的 Windows 资产是后来两次替换的构建，Docker latest 也仍指向 0.4.32。0.4.34 全程走桌面发版工作流：tag、Release 资产与 latest 均由 publish 流程一次生成并校验，不再手工替换资产。

新增设置入口（按旧 Python 版 SetupWizard 7 页复刻，WebUI 与桌面壳同一套界面）：

- 四站 Cookie：可持久保存（存 Vault，永不回显，留空保留原值）；搜索、预检、下载优先用本次 Cookie，已存值只作回退。
- AI 设置：启用、地址、模型、API Key、测试连接；启用后接通生产核对模型。
- qBittorrent：地址与登录可保存 + 连接测试；下载时空白字段用已存设置补齐。
- 流媒体回退顺序：可编辑保存，回退按保存顺序走。
- FlareSolverr：设置 + 连接测试；启用的服务只接管遇到浏览器挑战的只读请求，直连仍是首选；managed 模式可随程序启动并停止。
- 音乐库：库目录可配置，新发布写入保存目录；Plex / Navidrome 设置 + 测试，入库后通知，失败只记说明不阻断发布。
- 歌单：上传 / 粘贴 / 挂接（incoming/playlist-<jobID>.m3u）+ 已存歌单库，搜索时可直接选歌单。

其余与 0.4.33 相同：全量迁移到 Go（桌面壳、核心、打包与 Docker 入口全部改为 Go 实现，安装包与镜像内不再有 Python 运行时，不再解压 Python DLL）；桌面壳为 Go 原生（Wails v2.17.1），窗口直接渲染与 Docker 相同的 WebUI；凭证库为 Go 实现的三平台 Vault（Windows DPAPI、macOS Keychain、Linux AES-GCM），与旧 Python 版格式互通，升级保留已有凭据；自动更新为 Go 实现（GitHub Releases 检查 + SHA-256 校验 + 交接安装）；配置迁移（旧 Python 配置可迁移到 Go 核心，只读读取，幂等，留有收据）；命令行工具 version / status / jobs / job / control / stop / migrate；执行器：真实下载（qBittorrent）、转码（WAV→FLAC）、流媒体回退与歌单导入、目录接线（真实 MusicBrainz 查询）、媒体处理（NCM 解密、FLAC 标签、LRC、去重、艺人文件夹）；Docker 镜像入口改为 Go 二进制，无 Python 运行时；健康检查走 `musicops healthcheck`；冒烟测试与发版门禁均为 Go 实现；许可证由 `go list -m` 收集进包内 `licenses/`。

已知缺口（未完成，不当作已完成）：托盘图标装不上（Wails v2.17.1 无公开 API），`--minimized` 只能最小化到任务栏/Dock；桌面壳未在真实 Windows/macOS 硬件上跑过（以 CI 构建为准）；更新完整流程未在真机上走完；`core.log` 只在下次启动时轮换（单次运行内仍会增长，超过 8 MB 时保留为 `core.previous.log`）；任务级 retry 仍被核心拒绝；取消只在检查点被观察。歌词拉取、Discogs 目录核对、十平台歌单读取、网易云引擎、musicdl、Roon 尚未接线（仅设置与测试入口）；真实 AI 调用需用户填入自己的地址与 Key，线上逐笔扣费格式、真实四站凭证与 qBittorrent 端到端、OpenCC 仍未接入。

注意：Docker 容器里，之前用 12–15 字符密码的用户升级后会看到明文启动错误而非静默复用（有意为之，否则核心会无明确原因退出）。本版 tag 的源码树仍包含旧 Python 源码（构建时仍需用到其中的图标与版本文件），删除放在同步到 main 时进行；安装包与镜像内已无 Python 运行时。

提供 Windows 安装版与便携版、macOS Apple Silicon PKG/DMG/ZIP，以及 Linux amd64 原生 HTML WebUI 镜像 `wsdbb72/muiscops:latest`。macOS 使用 ad-hoc 签名，尚无 Developer ID 公证。详见[性能与临时目录](性能与临时目录.md)。
