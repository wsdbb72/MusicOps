MusicOps 0.4.32 接入 Go 核心工作流原子衔接，入库、发布与操作页的链路改为真实可跑的闭环。

- 工作流阶段、领域证据、任务完成和后继队列边进入同一次 Pebble 条件批写：同一请求 ID 可重放，并发完成只有一个胜者，旧 owner / fence 不能推进工作流，已取消时不创建后继。
- 四站检索（open.cd、dicmusic、orpheus、redacted）分类门禁：无结果、不匹配、认证、限流、访问受限、网络、暂时失败、解析或契约错误分开记录，认证失败不是空结果；精确命中才进入 requesting，搜索不能直接进入 downloading。
- 跨站身份合并加入发行年份证据：发行年份冲突时否决合并，避免把不同发行拼成同一张专辑。
- 本地音频入库语义修正：本地导入不是下载，回执里 downloaded 恒为假，只有 library_published 为真；任务进度显示「已入库」，不再显示「已完成」。
- POST /v1/audio/release 改为每轨独立：每轨有自己的请求 ID 和记录，并带 origin 区分（manual / local_import）；提交失败时只清理本次请求的孤儿文件。
- 新增 incoming 投递入口 POST /v1/audio/incoming：上传 .wav/.flac（32 MiB 上限）到 incoming/，已存在的文件不覆盖，返回 SHA-256；音频仍只由 /v1/audio/release 校验后入库。
- publish_album 注册为执行器（现共 5 个键），执行前重新核对库记录（文件仍在且哈希一致）才完成任务；种子保存仍停在待核对，不算下载或入库。
- 操作页站点、库、日志接上真实功能：站点页保存默认四站选择，库页列出全部已校验入库的记录（含文件是否还在），日志页列出最近任务活动；批量操作仍未接。
- WAV/FLAC 校验规则统一：无 ffmpeg/ffprobe 时结构检查也可接受（structural），有解码器时升级为完整解码；解码器拒绝文件时仍拒绝。
- 发布加任务阶段校验：失败、已取消、未确认身份的任务不能发布；needs_review 仍可发布，核对针对的是获取路径，不是刚校验过的音频。

真实四站下载、真实 AI 调用与线上逐笔扣费格式仍未接入；Muse Wonder 终审尚未进行。本版仍使用 SQLite 作为主库；Go/Pebble 工作流引擎随包提供。

提供 Windows 安装版与便携版、macOS Apple Silicon PKG/DMG/ZIP，以及 Linux amd64 原生 HTML WebUI 镜像 `wsdbb72/muiscops:latest`。macOS 使用 ad-hoc 签名，尚无 Developer ID 公证。详见[性能与临时目录](性能与临时目录.md)。
