MusicOps 0.4.31 改善大档案任务列表读取和后台磁盘占用，加入可选 SSD 临时目录。

- 任务中心改用持久小摘要、专辑当前阶段和待执行队列索引分页，刷新时不再读取全部执行清单或逐条重建专辑链。隐藏后继仍参与当前阶段选择，防止删除后重新出现旧阶段。
- 全量 AI 登记和 FL 批量授权先按所需任务状态筛选，减少无关历史清单读取。
- 复制、哈希、解密和解码共用可重入磁盘并发槽，HDD 默认2项，可在桌面/Web设置中调整为1–8。网络检索继续独立运行，等待磁盘名额时仍检查暂停和取消。
- Windows 后台和受管理子进程设置并回读 VeryLow I/O 优先级，继续使用已有小核、EcoQoS和低 CPU 优先级策略；系统不支持时明确报告。
- “连接与设置 → 音乐放在哪里”加入独立临时下载与处理目录，默认关闭、建议有 SSD 时启用。现有任务保持原路径，备份和做种原件仍位于音乐库同级。
- 修复 SSD/HDD 跨盘入库：在最终库同盘、监听范围外完成暂存和校验后原子发布；成品与做种迁移确认后清理本任务下载、整理和已提交事务暂存音频，保留备份和做种原件。
- 数据库索引原子升级至 schema 2，保留历史任务、配置、凭据和事务。首次升级大档案可能需要几分钟；回退旧版必须恢复升级前完整档案。
- Windows EXE 的数字版本和文本版本统一从项目版本生成，移除需要重复手改的旧版本资源文件，并在构建前验证主程序和后台程序的版本资源。

本版仍使用 SQLite；尚未完成的 Go/Pebble 重构和实验性大清单压缩未进入正式包。

提供 Windows 安装版与便携版、macOS Apple Silicon PKG/DMG/ZIP，以及 Linux amd64 原生 HTML WebUI 镜像 `wsdbb72/muiscops:latest`。macOS 使用 ad-hoc 签名，尚无 Developer ID 公证。详见[性能与临时目录](性能与临时目录.md)。
