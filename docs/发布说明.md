MusicOps 0.4.35：令牌与去重两条线收尾，界面换成设计系统，歌词封面与网易云接入本体。

令牌与下载

- RED 与 DicMusic / Orpheus 共用同一套令牌账本：余额解析、观察提交、复核、迁移导入、获取判定都走同一个 `IsTokenSite`。
- 未对账的令牌请求 30 分钟后自动到期，不再永久占住整个站点；同资源仍然拒绝第二次 `usetoken`。
- 后台每 30 秒对账：余额下降判为已扣费，余额 5 分钟不变判为未扣费；只用已保存 Cookie，每站读余额至少间隔 60 秒。
- 账户余额在渲染页上按账号绑定（同页必须出现 `user.php?id=<账号>`）：DicMusic 的接口文档没有令牌字段，此前它的余额永远读不到。
- 令牌待核对的种子已保存时可以直接继续下载；下载只读本地种子，不会再发 `usetoken`。
- 下载中可暂停 / 恢复 / 重新校验 / 删除种子（保留文件）；取消落在执行器启动前也不会再卡死。

音乐库与刮削

- 批量刮削按专辑只查一次目录，可选同时取歌词与封面（一次最多 30 首）：先取后写，取不到就整首不动，封面写失败会恢复备份。
- 字段锁与去重抑制：按专辑目录保存，字段锁让自动写入跳过指定字段（勾选覆盖也不改），抑制让该专辑不参与重复扫描与合并。
- 合并重复时先用副本补齐保留文件的空字段并同步摘要，文件仍被 qBittorrent 做种则拒绝合并。
- 去重前的做种检查在 qBittorrent 不可达时保守拒绝，而不是当作安全。

歌词、封面与网易云

- 歌词与封面按 LrcApi 契约接入：地址、路径、鉴权取自「歌词与封面服务」设置，404 视为没有这一首并继续写标签，网络失败整单拒绝。
- 非回环只允许 HTTPS；带凭据时不跟随跳转，不带凭据最多 3 跳（公开服务的封面会 301 到 CDN）。
- 网易云歌单：详情只给少量曲目 + 全部 trackIds，其余按 100 一批补全，6000 首以内不再截断；分享链接带 `uct2` 参数也能解析。
- 内置网易云：保存账号 Cookie 后自行搜索并只取无损 FLAC，不依赖外部引擎；账号没有无损权限时如实报「只有有损音频」，不把 mp3 存成 FLAC。

界面

- 样式改为令牌化设计系统：颜色/字号/间距/圆角/阴影全部走变量，深色跟随系统；宽屏左侧栏、窄屏横向导航；补焦点环与「减少动效」。
- 修掉两处真实缺陷：卡片内所有按钮被一条通配规则压平成纯文本；种子控制按钮渲染了却从不显示。
- 待核对列表改为服务端筛选 + 游标分页，「加载更多」按游标追加，队列超过一页不再丢任务。

稳定性与接口

- 执行器 panic 的完整栈脱敏后写入 `panic.log`（1 MiB 轮换），任务行只保留首帧；`core.log` 在下次启动时轮换。
- `/v1/open/*` 是给外部软件的稳定面（解析歌单、检索、任务、核对、下载、种子控制、目录识别、入库、标签），配 OpenAPI 3.1 契约与 `X-API-Key`；独立入库不依赖工作流任务。
- 任务列表只对当前页出现的 root 做前缀查询，不再每次全量扫描专辑索引。

已知缺口（未完成，不当作已完成）

- 令牌 `in-flight` 上限仍为 1（文档写 2），提高需要真实未知扣费同时发生的验证。
- TIDAL / Apple Music / QQ 音乐仍依赖用户自行安装的 go-music-dl（AGPL，不随包分发）；Roon 需要用户的 Roon Core 才能验证。
- 桌面壳未在真实 Windows/macOS 硬件上跑过（以 CI 构建为准）；更新完整流程未在真机上走完。
- 迁移（旧 Python 配置/任务库）已完成备份与失败不阻断，但没有分段进度与半导入清理。

MusicOps 0.4.34：0.4.33 的干净重发（tag、资产、Docker latest 三者一致）+ 补齐设置入口。

本版取代 0.4.33：0.4.33 的 tag 指向的是有 bug 的旧代码，而 Release 里的 Windows 资产是后来两次替换的构建，Docker latest 也仍指向 0.4.32。0.4.34 全程走桌面发版工作流：tag、Release 资产与 latest 均由 publish 流程一次生成并校验，不再手工替换资产。

新增设置入口（按旧 Python 版 SetupWizard 7 页复刻，WebUI 与桌面壳同一套界面）：

- 四站 Cookie：可持久保存（存 Vault，永不回显，留空保留原值）；搜索、预检、下载优先用本次 Cookie，已存值只作回退。
- AI 设置：启用、地址、模型、API Key、测试连接；启用后接通生产核对模型。
- qBittorrent：地址与登录可保存 + 连接测试；下载时空白字段用已存设置补齐。
- 流媒体回退顺序：可编辑保存，回退按保存顺序走。
- FlareSolverr：设置 + 连接测试；启用的服务只接管遇到浏览器挑战的只读请求，直连仍是首选；managed 模式可随程序启动并停止。
- 音乐库：库目录可配置，新发布写入保存目录；Plex / Navidrome 设置 + 测试，入库后通知，失败只记说明不阻断发布。
- 歌单：上传 / 粘贴 / 挂接（incoming/playlist-<jobID>.m3u）+ 已存歌单库，搜索时可直接选歌单。

其余与 0.4.33 相同：全量迁移到 Go（桌面壳、核心、打包与 Docker 入口全部改为 Go 实现，安装包与镜像内不再有 Python 运行时，不再解压 Python DLL）；桌面壳为 Go 原生（Wails v2.17.1），窗口直接渲染与 Docker 相同的 WebUI；凭证库为 Go 实现的三平台 Vault（Windows DPAPI、macOS Keychain、Linux AES-GCM），与旧 Python 版格式互通，升级保留已有凭据；自动更新为 Go 实现（GitHub Releases 检查 + SHA-256 校验 + 交接安装）；配置迁移（旧 Python 配置可迁移到 Go 核心，只读读取，幂等，留有收据）；命令行工具 version / status / jobs / job / control / stop / migrate；执行器：真实下载（qBittorrent）、转码（WAV→FLAC）、流媒体回退与歌单导入、目录接线（真实 MusicBrainz 查询）、媒体处理（NCM 解密、FLAC 标签、LRC、去重、艺人文件夹）；Docker 镜像入口改为 Go 二进制，无 Python 运行时；健康检查走 `musicops healthcheck`；冒烟测试与发版门禁均为 Go 实现；许可证由 `go list -m` 收集进包内 `licenses/`。

已知缺口（未完成，不当作已完成）：托盘图标装不上（Wails v2.17.1 无公开 API），`--minimized` 只能最小化到任务栏/Dock；桌面壳未在真实 Windows/macOS 硬件上跑过（以 CI 构建为准）；更新完整流程未在真机上走完；`core.log` 只在下次启动时轮换（单次运行内仍会增长，超过 8 MB 时保留为 `core.previous.log`）；任务级 retry 仍被核心拒绝；取消只在检查点被观察。musicdl、Roon 尚未接线（仅设置与测试入口）；内置网易云已接线（保存账号 Cookie 后自行搜索并只取无损 FLAC，不依赖外部引擎）；真实 AI 调用需用户填入自己的地址与 Key，线上逐笔扣费格式、真实四站凭证与 qBittorrent 端到端、OpenCC 仍未接入。

注意：Docker 容器里，之前用 12–15 字符密码的用户升级后会看到明文启动错误而非静默复用（有意为之，否则核心会无明确原因退出）。本版 tag 的源码树仍包含旧 Python 源码（构建时仍需用到其中的图标与版本文件），删除放在同步到 main 时进行；安装包与镜像内已无 Python 运行时。

提供 Windows 安装版与便携版、macOS Apple Silicon PKG/DMG/ZIP，以及 Linux amd64 原生 HTML WebUI 镜像 `wsdbb72/muiscops:latest`。macOS 使用 ad-hoc 签名，尚无 Developer ID 公证。详见[性能与临时目录](性能与临时目录.md)。
