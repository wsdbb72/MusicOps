# 开发与验证

MusicOps 的核心、桌面外壳、本地 WebUI 与 Linux 容器均由 Go 实现。应用不需要 Python；发布工具、Windows 安装器测试及第三方 FlareSolverr 的构建仍使用 Python。

- `native/core/cmd/musicops`：本地 HTTP 核心和 WebUI。
- `native/core/cmd/musicops-desktop`：Windows/macOS 外壳、核心进程管理和更新。
- `native/core/internal`：任务、持久化、下载、媒体校验与入库、凭据与外部服务。
- `packaging` 和 `docker`：安装器、便携包、第三方工具、容器及验收脚本。

## 本机回归

安装 Go 1.26 和可用的 FFmpeg、ffprobe，然后在 `native/core` 运行：

```sh
go vet ./...
go test ./... -count=1
```

使用临时档案、合成音频和模拟服务。真实账号、种子和音乐库不参与发布测试。Windows 的符号链接用例需要相应权限；Windows 安装器测试需使用 Inno Setup 7，通过 `INNO_ISCC` 指定 `ISCC.exe`，在根目录运行 `python -m pytest tests/test_windows_installer.py`。这六项用例使用独立 AppId 和隔离目录，不影响已有安装。

## 发布

版本号由根目录 `VERSION` 维护。推送 `codex/release-*` 启动 [完整发布流程](../.github/workflows/desktop-release.yml)。它对同一个提交执行 Windows 原生安装/重装及可执行文件验收、macOS Apple Silicon 实机安装/重装、Linux amd64 容器烟测。Windows 用 `packaging/build_windows_go.ps1`，macOS 用 `packaging/build_macos_go.sh`，容器用 `docker/Dockerfile`。

所有平台通过后，流程核对构建清单及 SHA-256/512，再发布 Windows 安装器与便携包、macOS arm64 PKG/DMG/ZIP、源码 ZIP；GitHub Release 发布成功后才推进 Docker `latest`。发布完成后，将对应的已验收提交同步到 `main`。不覆盖已有版本。
