# 开发与验证

应用由 PySide6 GUI、独立 worker、SQLite 状态、域名绑定的 DPAPI 凭据和服务适配器组成。GUI 通过本地 IPC 提交任务，长任务在后台执行。

## 本地开发

使用 Python 3.12 或以上版本创建虚拟环境，安装 `requirements.lock` 与可编辑工程，再运行 `python -m pytest -q`。测试使用临时目录和模拟服务；少量媒体验证测试需要可用的 FFmpeg／ffprobe。

`config/example.json` 展示通用配置形状。实际服务地址、鉴权与音乐目录应在本地档案中配置。可运行 `scripts/export_config_schema.py` 重新生成公开配置示例与 JSON Schema。

## 证据边界

`index_library(..., metadata_only=True, checkpoint=...)` 返回元数据级只读证据，音频 SHA256 保持空值，解码状态为未运行。每 50 个音频文件调用检查点，可用于取消或暂停。原始标签摘要有大小预算，二进制封面不会在任务结果中展开。

文件名与标签冲突、缺少发行信息、版本不一致、时长不明或未完成完整解码时，匹配保持待复核。在线资料候选与音频完整性验证是独立证据。

公开测试使用合成歌单和虚拟域名。新增服务适配器时应测试请求白名单、响应大小、超时、取消、鉴权失败、身份冲突与部分响应，不在测试中嵌入实际 Cookie 或密钥。

## 打包

`packaging/build_windows.ps1` 生成 Windows 文件夹包。源码仓库不分发 FFmpeg 等第三方媒体工具二进制；如自行加入工具，应收集与具体版本匹配的许可证、来源及必要对应源码。

运行包验证应使用新建临时档案，确保首次启动、GUI／worker 通信、设置保存和失败场景均可复现。构建日志、个人运行报告和配置档案属于本地内容，不提交公开仓库。

## GitHub Actions

Windows CI 使用 Python 3.12、锁定依赖与合成测试。Chocolatey 只在临时 CI runner 中安装 FFmpeg／ffprobe，不打包或上传媒体工具、运行档案与个人报告。工作流没有自动发布或上传 archive 的步骤。

配置参考 [GitHub Python 测试指南](https://docs.github.com/en/actions/tutorials/build-and-test-code/python)、[官方 setup-python](https://github.com/actions/setup-python) 与 [Chocolatey install 文档](https://docs.chocolatey.org/en-us/choco/commands/install/)。
