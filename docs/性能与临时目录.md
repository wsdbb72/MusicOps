# 性能与临时目录

MusicOps 0.4.31 的桌面和 Web 设置使用相同规则。

## 选择存储位置

打开“连接与设置 → 音乐放在哪里”。音乐库可以在 HDD；未启用独立临时目录时，下载和整理仍位于音乐库同级的 `MusicOps` 文件夹。

有 SSD 时，可勾选“启用独立临时下载与处理目录”，选择一个专用完整目录，建议至少有 20 GB 空间。没有 SSD 就保持关闭。程序不自动选择系统盘，也不会把现有任务或正在下载的种子强行迁移到新目录；新任务使用新设置，已有任务沿用其记录的目录。

Docker 中填写容器内路径，并在 compose 中把 SSD 文件夹挂载到该路径，例如 `/ssd-work`。仅填写宿主机路径不会创建挂载。运行账号必须有读写权限。

| 内容 | 所在位置 |
| --- | --- |
| 下载与整理副本 | 启用时在所选临时目录，未启用时在音乐库同级 |
| 验证后的成品 | 设置的音乐库 |
| 原音源备份、隔离和报告 | 音乐库同级 `MusicOps` |
| PT 做种原件 | 音乐库同级 `MusicOps/seeding` |

跨 SSD/HDD 时，整理完成后复制到最终库同盘、监听范围外的暂存区，验证后原子改名发布。只有成品校验通过、相关 qBittorrent 做种路径迁移确认完成后，才清理本任务拥有的下载、整理和发布暂存音频。备份与做种原件继续保留；失败时保留可恢复副本，不清空整个临时文件夹。

## 控制后台占用

“同时读写磁盘的任务数”范围为 1–8，HDD 推荐保持默认 2。它限制复制、哈希、解密、解码等重磁盘操作，不占用网络检索名额。等待磁盘名额期间仍检查暂停和取消。

Windows 后台及受管理子进程继续使用已有的小核、较低 CPU 优先级和 EcoQoS，并尝试设置 VeryLow I/O 优先级后回读确认；系统不支持时报告不可用。它们降低对前台的干扰，不保证 HDD 在大文件处理中完全没有占用。

## 任务中心与升级

任务列表改为读取持久小摘要和专辑当前阶段索引；仅执行具体任务时加载完整清单，避免每次刷新扫描全部历史。隐藏后继阶段仍参与专辑当前阶段选择，删除后不会重新显示旧阶段。

第一次从 0.4.29 升级时会原子建立摘要和队列索引，大档案可能需要几分钟；请等待后台初始化，不要反复启动。原任务、凭据、配置和事务清单保留。数据库 schema 升至 2；需要回退 0.4.29 时应恢复升级前完整档案，不能只替换旧 EXE。

本版仍使用 SQLite，未加入尚在开发的 Go/Pebble 数据库替换，也没有启用实验性清单压缩。后续数据库迁移将独立验收。
