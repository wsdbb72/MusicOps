# MusicOps 操作指南

本指南对应 **MusicOps 0.4.3**。Windows 推荐使用 `Setup.exe`：检测到旧版时更新原目录，未找到才进入新安装；绿色版未被找到时，在目录页选择原来的 MusicOps 文件夹。配置、凭据、任务和已有媒体工具会保留。更新前先安全退出应用及后台，具体见 [更新步骤](运维与恢复说明.md#如何更新应用)。

Mac 新版仅提供 Apple Silicon `arm64` 的 `.pkg`；历史 Intel 附件保留。双击后按系统安装向导安装，完成后从“应用程序”打开 MusicOps。ZIP 是保留的手动安装方式。升级前，在“任务中心”点击“退出应用及后台”；正在执行的任务需要完成或取消后再退出。安装器保留用户资料和钥匙串凭据。

[返回首页](../README.md) · [备份与恢复](运维与恢复说明.md)

MusicOps 有五个主要页面：**歌单入库、资料补全、音质升级、任务中心、专辑搜索**。先通过 **连接与设置** 保存运行所需信息，再选择要做的事；前三个工作流的进度和核对事项都在任务中心查看，手动专辑搜索单独显示检索结果。

## 首次配置速查

每一步都可以跳过，已有服务以后还能修改。完整图文结构与填写说明见 [README 的七步配置](../README.md#第一次使用七步配置)。

| 向导步骤 | 必要内容 | 可以跳过的部分 |
| --- | --- | --- |
| 音乐放在哪里 | 选择存放成品音乐的目录 | 暂不使用 Roon 可不勾选 |
| 连接四个资源站 | 有账号的站点：JSON Cookie + 参与检索 | 没有账号的站点关闭 |
| 连接 qBittorrent | 站点下载需要 WebUI 地址、用户名、密码 | 只补全已有文件时可跳过 |
| 网易云回退与媒体工具 | 整理和验证需要 FFmpeg、ffprobe 路径 | API、网易云登录态、客户端下载目录均可选 |
| 歌单平台授权 | 遇到登录要求时，选择对应平台填写 Cookie / Token / API Key | 九个新增平台授权均可跳过，先尝试公开读取或导入文件 |
| 补全封面、歌词与资料 | 使用私人歌词服务时填地址、完整鉴权原文 | Discogs、AI、私人歌词服务可跳过 |
| 连接 Navidrome | 启用时填服务地址、用户名、密码 | 只用 Roon 或暂不接入时跳过 |

保存后可以开始使用。使用 Roon 时，还要在 **Roon → 设置 → 存储** 添加所选音乐库。Navidrome 需要读取同一批文件，远程或容器部署要核对挂载映射。

## 凭据已保存时如何修改

Cookie、密码、接口鉴权、Token 和 API Key 等已保存项，会显示点号 / 星号及保存状态提示。**显示的是状态掩码，不是从保险库取出的真实值。**

- 保留掩码不改动：继续使用原凭据。
- 输入新内容或导入新的 JSON：保存后替换对应凭据。
- 新值留空：保留已保存值，不把空文本当作新凭据。
- 修改服务主机名：旧凭据不会自动转发到新域名，需要重新填写。
- 关闭“参与检索”或某项服务的启用开关：暂停使用该连接，已有保存值仍可保留。

qBittorrent 更新密码时也需要填写对应 WebUI 用户名。歌词接口鉴权填写服务提供的完整 `Authorization` 原文，无需自行加 `Bearer`；服务原文已包含此前缀时完整保留。不同服务的密钥不能互相代替。

### JSON Cookie 导入失败或登录失效

1. 重新打开对应网站，确认浏览器内仍能访问账号页面。
2. 从该站当前页面用 Cookie-Editor 导出 **JSON**，导入到同一站点。
3. 检查它是 `[` 开头的对象数组，不是账号密码、链接或 HTTP 请求头文本。
4. PT 站点确认勾选“参与检索”；歌单授权页选对平台并保存，然后重试。

导入时会检查 Cookie 所属域名；其他站点的 Cookie 不会被当作该站凭据。`已保存`只证明本地存有凭据，无法保证网站登录态尚未过期。请勿把 JSON 内容粘贴到 Issue、聊天记录或公开日志。

### 歌单平台授权填写

PT 下载站点与歌单来源平台的授权分开保存。新增的 **歌单平台授权（可选）** 页提供 QQ、汽水、酷狗、酷我、咪咕、bilibili、Spotify、Apple Music、YouTube 的选项；网易云登录态仍在回退配置页。

国内平台与 bilibili 使用对应域名 Cookie JSON。Spotify 填 OAuth Access Token，Apple 填 Developer JWT，YouTube 填 API Key 或 OAuth Access Token；这些不是账号密码，MusicOps 不自动获取或刷新它们。具体 JSON 写法与平台限制见 [平台与授权指南](references/global-playlists.md)。

### AI 自动兜底怎么开启

在 **补全封面、歌词与资料** 页填写兼容 Responses 的 API 地址、模型名称与 API Key。输入新密钥后会默认勾选 **启用 AI**；保存前可自行取消，未配置 AI 也能使用其余功能。凭据已有掩码时保留原值即可，不用重复填写。

识别顺序是 **API → 公开音乐资料网站 → AI 联网搜索**。API 已准确匹配时直接复用；未匹配时尝试读取网站允许访问的页面；仍不能确认时才调用 AI 联网。AI 服务和所填模型必须支持 Responses `web_search`，缺少实际搜索记录或来源链接会显示失败原因，不能用普通聊天接口的模型记忆冒充联网。只有文件名可用时，也可将文件名作为检索提示。最终仍需核对发行、曲目与时长。

核对窗口显示已读取网页和 AI 联网来源的可点击链接，也允许自行填写或修改资料。网站要求浏览器验证、限制自动访问或页面格式不支持时会留下原因；Album of the Year 需要网站许可，继续提供人工入口。四站无匹配时，可用核验过的规范别名再次搜索，原来的歌曲和发行约束继续有效。AI 调用失败会保留 API 和网站结果。

联网查到名称或署名而本机尚未读到详情时，下拉框会标明 **AI 联网线索（待核实）**。选择曲目行，再点“用所选目录候选填入当前曲目”，即可填写后继续手动修改；检查来源和完整时长后再保存。线索本身不会触发下载或标签写入。

自动识别每次最多两次模型请求和两个替代检索词；联网请求可能包含多次服务端搜索并产生费用。仅提供当前对象、必要候选与文件名提示，不发送整座音乐库、目录路径或凭据。任务中心的 **AI 辅助勾选** 会重新查询资料或推荐已观察到的音源，并把建议填入可编辑的核对窗口。用户检查后点击保存或采用才生效。

## FL 免费下载设置

如果站点提示浏览器验证，点**连接与设置 → 浏览器验证与内置 FlareSolverr 设置**，勾选 **使用程序内置 FlareSolverr（自动配置与启动）** 和 **遇到浏览器挑战时使用本机 FlareSolverr**，点 **保存设置**，再点 **启动并测试 FlareSolverr**。Windows 与 macOS ARM 均已包含服务和浏览器，无需独立安装或配置地址；已有服务可取消内置选项后填写本机地址。Cookie 仅交给本机服务，浏览器 User-Agent 和验证 Cookie 配套复用。登录失效和限流仍需更新授权或稍后重试，下载和 FL 请求不会重复点击。

“最多使用 FL 免费下载”用于 DicMusic / Orpheus / RED，按本批工作流计数：

| 设置 | 行为 |
| --- | --- |
| `0 次 / 批次` | 不使用 FL，只采用已免费的资源 |
| `X 次 / 批次` | 本批最多使用 X 次 FL |
| 勾选“全部” | 次数框变灰并忽略其数值，本批不设次数上限 |

“全部”不改变这三个站点只使用免费路径的规则。程序仍检查站点余额、实际免费状态和种子身份。余额不足、免费状态未知、接口超时或请求结果不明时，任务会等待核对，不自动重复请求。OpenCD 直接获取种子，不消耗这里的 FL 额度。

## 歌单入库

1. 在 **歌单入库** 选择自动识别并粘贴支持平台的歌单链接 / 分享文本；输入纯 ID 时先选择平台，点击 **解析歌单**。
2. 勾选需要入库的曲目；**全选 / 取消** 切换全部可见条目。
3. 点击 **开始入库**。任务中心先显示本次本地库检查，再为缺失需求生成识别任务。
4. 身份核对后生成独立搜索任务；找到资源后进入下载与入库。展开分类和专辑可查看歌曲明细。

网易云与其他已实现的分页路径不会在本地硬截断为前 1000 首。各平台公开可见范围不同，Spotify 等公开预览不等于全量；上游清单不完整时会警告，仅处理用户明确选择的可见曲目。音乐库中身份、专辑和已知时长匹配的曲目跳过，余下需求按专辑合并。

资源站通常提供整张发行，所选曲目可能带来整张专辑下载。若歌曲或专辑身份不明确，先在任务中心核对，不会用另一首同名歌曲替代。

**本地库扫描在站点搜索之前。** “已检查 X 个音频文件”统计音乐库中的本地文件，与歌单条数不是同一计数。例如歌单只有 4,080 首，本地库有 10,000 多个音频文件，扫描数可以超过 4,080；详情会另列本批歌单选择数。不要因此重复点击开始。

### 导入歌单文件

点击 **导入文件**，选择 JSON、CSV、TSV、TXT、M3U / M3U8 或普通 XLSX。优先使用保留平台、原 ID、艺人、专辑与时长的 JSON；常见带中英文列名 CSV 也可使用。

TXT 导入时明确选择 **歌名 - 歌手** 或 **歌手 - 歌名**，防止两列反转。没有列名的表格或有歧义的分隔符不会按位置猜测。M3U 只读取 EXTINF，XLSX 只读取普通单元格；不会打开音源路径、执行脚本、宏、公式或外部工作表。带公式的工作簿请另存为纯值 CSV。

单文件 20 MB、50,000 首；UTF-8 / BOM 优先，GB18030 回退会标明。缺少专辑、歌手或时长的文件仍会保留缺失状态；需要补足可靠资料，不能只填“未知”来强行入库。

### 网易云回退的条件

四站逐个独立检索。正常空结果显示“未找到资源”；某站登录、网络或限流失败，只显示该站原因，其他站点继续。可用站点没有匹配发行，且开启网易云回退时，可以继续尝试网易云；已启用站点全部不可用时，先检查连接再继续。未启用站点和未返回的页面不算“已检索无资源”。

回退支持直接获取完整可用音源，也可以接入已经下载好的客户端文件。可选 API 服务需要提供 `/song/url` 响应，自定义 API 的账户权限由该服务负责。API 不可用或网易云只有试听、无完整下载权限时，保留具体原因，不保证所有歌单曲目都能获取。

其他平台的 ID 不会被当作网易云 ID。跨平台回退前必须得到唯一的网易云歌曲引用，歌名、艺人、专辑和完整时长都要匹配；缺少可靠资料或存在多个候选时等待核对。视频频道与 UP 主不自动作为音乐歌手。

接入客户端下载目录时，按照歌曲、艺人、专辑资料匹配。多个相同曲目版本无法唯一判断时需要处理冲突。NCM 在工作副本中解密；原 NCM 不变，做种源不变。过大的导入目录可改选具体专辑子目录。

## 资料补全

点击 **检查并自动补全** 后，检查已有音源的歌曲、艺人、专辑、专辑艺人、封面、同步 `.lrc` 和多碟编号等资料。可靠证据可以自动补齐；资料冲突、曲序缺失和被锁定字段会转为待核对。

封面与歌词可能确实没有可靠来源。界面会区分“暂无匹配资料”和鉴权、网络失败；后者需要先处理连接。无歌词不等于音频损坏。选择跳过某次资源服务时，仅按该次确认继续。

暂无资料的结果会短期缓存，避免反复访问同一服务。需要立即重新查询时，点击 **重新查询暂无资料**。

同步歌词与音频同名，例如 `01 - Song.flac` 对应 `01 - Song.lrc`。多碟专辑会核对碟号与总碟数；不能把不同录音或不同发行仅按同名合成一张专辑。

## 音质升级

点击 **检查并自动升级** 后，先识别现有音源，再从已启用站点寻找候选。站点给出的格式和音质信息用于筛选，下载后还会检查实际媒体信息、曲目完整性、时长和解码结果。

对于同一录音与发行：有损同编码音源可比较有效码率，无损音源比较位深和采样率；不同声道和身份不明的候选不会自动替换。高码率无损文件未必更好，24 bit 也不代表一定来自更好的母带。

新版完整验证并成功入库后，旧版才移出音乐库监听目录，保留恢复内容。缺少同一发行 ID 时，先在任务中心核对版本。程序不会因候选文件名写着“Hi-Res”就删除现有版本。

## 手动专辑搜索

在第五个页面 **专辑搜索** 输入艺人或专辑关键词：

- **原样搜索**：保留输入文本，向已启用的四个资源网站发起检索。
- **识别专辑后精准搜索**：先从 MusicBrainz / Discogs 选择确认的发行，再用标准艺人和专辑名称搜索，并过滤名称或艺人不匹配的结果。

看到多个发行版本时，先核对版本再选择。结果会显示站点、音质和做种数量，以及每个站点本次检索的状态；某站失败不清空其他站的结果，正常没有结果也不会报成站点故障。列表展示接口当前返回页，更多资源可点击 **打开选中资源详情** 继续核对；此页面不自动下载，搜索成功也不等于已建立入库任务。

## 任务中心的操作

先展开顶部分类，再展开专辑查看歌曲。**识别任务**显示本地库检查和歌曲 / 专辑资料核对；**搜索任务**显示四站查询；**下载与入库**显示后续下载、补资料、音频验证与发布。识别、搜索和后续处理保留独立记录，完成一类不会把前一类结果覆盖掉。

点击一行是查看详情；左侧复选框用于批量选择。可以勾选多个任务、点 **勾选本页**，或勾选某分类选择本页该类任务。翻页保留勾选，“已勾选”计数会提示其他页还有多少项；每批最多 **500 项**，需要重新选择时点 **清空勾选**。

| 操作 | 作用 |
| --- | --- |
| 点击任务 / 展开专辑 | 查看当前步骤、站点结果、歌曲资料和需要处理的信息 |
| 暂停勾选 / 继续勾选 | 批量控制后续阶段；暂停在当前阶段完成后生效 |
| 取消勾选 | 批量停止后续处理，已发布内容和做种保留 |
| 核对当前专辑 | 按提示确认当前任务的候选、发行、曲序、资料、封面或修复后的连接 |
| 重试失败勾选 / 重试当前任务 | 使用当前连接设置重新执行失败步骤；站点故障后可重新搜索 |
| 删除勾选 | 取消后续处理并移除记录，保留音乐、下载、做种和审计证据 |
| AI 辅助勾选 | 登记全部勾选的待核对项目；后台自动核实资料、候选或搜索词，可靠证据自动提交，歧义最后人工核对 |
| 恢复当前任务原版 | 检查恢复内容和当前文件后，回退当前任务的文件替换 |
| 暂停整个后台 / 继续整个后台 | 控制整个 MusicOps 队列，与只控制勾选任务分开 |
| 退出应用及后台 | 后台空闲后安全退出，用于更新或备份 |
| 上一页 / 下一页 | 浏览分页任务，避免大批量任务拖慢界面 |

批量操作会逐项报告已处理、跳过或未完成的数量。已结束或需要核对的任务不会通过“继续勾选”重新执行；需要核对时点击对应行，再用 **核对当前专辑**。勾选批次准备记录可控制其关联的未结束任务。恢复原版和发行确认只作用于当前任务，不会随勾选一次改动多张专辑。

AI 辅助使用持久化队列自动分批，不再只处理前 20 项。仅发送必要的当前对象和候选事实，不发送整座音乐库、私人路径、Cookie 或 API Key；已匹配资料、候选比较和曲目映射优先复用缓存。无法确认的项目会保留建议，可在“核对当前专辑”中修改资料、选择发行或调整搜索词。资料、错误原因和检索词改变后须重新评估；同一问题不反复调用 AI。

失败重试沿用同一下载与 FL 证据，不会新建一笔重复下载。资料缺失、候选歧义和文件事务不明确的项目会逐项说明跳过原因，请先打开核对窗口。删除会移除所选记录及后续记录，不删除音乐或停止做种。

**批次准备**也会作为任务显示，在扫描与创建专辑任务期间分别报告本地音频数、本批歌单选择数和当前阶段。若没有生成专辑任务，请先查看该批次的结果：全部需求已满足、近期资料检查缓存命中和真正创建失败含义不同。

从旧版更新后，之前尚未完成的准备请求会保留为“上次准备任务”记录，提示重新开始；多次点击积累的旧请求不会自动执行下载。返回对应入口，检查歌单选择和设置后重新开始即可。准备记录本身没有文件替换可恢复，恢复时应选择具体专辑任务。

需要核对的任务会等待选择，不是持续后台重试。FL 结果不明、qBittorrent 新增或启动状态不明时，先查看站点和下载器实际状态，避免重复操作。中断的文件事务会保留记录，恢复前仍会检查文件一致性。

关闭窗口后，后台继续；重新打开相同档案即可查看。换一个 `profile` 会看到另一套任务和设置。暂停或取消不会自动停止 qBittorrent 做种，也不会回滚已完成发布。

更新前点击 **退出应用及后台**。如果仍有活动任务，先等待完成，或自行取消后等到安全阶段再退出；单纯暂停不会保证后台已经停止。安装器发现文件被占用会提示重试，不会替你强制结束应用或取消任务。

## 遇到问题时

先看 [README 的状态与处理表](../README.md#任务中心与常见问题)。反馈时提供版本、操作入口、脱敏后的完整提示，以及问题发生在扫描、下载、整理还是入库阶段。不要发送整个私人运行档案。

音乐服务器未显示新文件时，确认文件已实际入库、服务器能读取相同目录、扫描已经结束，再在客户端搜索并播放。MusicOps 报告扫描请求成功不能代替客户端可见性与播放检查。

备份、更新、恢复与工作目录说明见 [运行档案与恢复](运维与恢复说明.md)。

若向导跳过所有 PT 账号，开启网易云回退的歌单仍可直接使用网易云；全部已启用站点访问失败则保留错误并等待检查，不当作无资源。

## 本地专辑资料库与更新

设置完成后后台建立索引，随后启动时按需增量刷新。首次扫描自动在私人档案的 `state/musicops.sqlite` 建立专辑与曲目的索引映射。资料补全页可查看专辑 / 预匹配曲目数量，并点击“更新本地资料库”或“查看专辑资料库”。后续扫描复用未变标签；歌单通过索引核对身份和时长，并验证命中文件仍然存在、版本未变。本地标签映射不等于已确认在线发行。

安装版正常启动时默认检查官方 GitHub 正式版，下载当前系统安装包并校验 SHA-256，后台安全退出后打开安装向导。按系统向导完成升级，原配置与工具保留。侧栏可手动“检查更新”，向导中可关闭启动自动更新。下载异常或校验失败不会执行安装。Mac 新版只提供 ARM 包。


## 0.4.4 任务与完整专辑补充

DicMusic / Orpheus 默认只走 FL 令牌或已确认个人免费路径。令牌不足时弹窗等待；普通下载必须在该弹窗明确授权一次或当前批次，可能计入下载量，不能由 AI 或重试操作暗中启用。旧未知请求先对账，切勿删除数据库强行重试。

如有令牌却被旧种子缓存拦截，更新至 0.4.5 后，在提示窗选择 **重新检查并使用 FL 令牌**，或在任务中心勾选后重试。程序重新核验当前个人免费、FL 按钮、余额和批次额度；两个站点统一带 `usetoken=1` 请求。已个人免费时复用缓存；旧缓存不再免费时可重新使用令牌，保留消费历史；未知请求只对账，不重复扣令牌。

任务中心可分类筛选、全量失败重试、全量 AI 核对及连续手动核对。手动保存成功后进入下一张，关闭窗口不保存。整专辑补全先取得完整发行曲目表，再只发布缺曲，不覆盖原音源。

其他流媒体回退使用安装包内置 go-music-dl，启用后自动配置本机服务；平台 Cookie 和扫码登录均在 MusicOps 设置页完成。已有外部服务也可手动连接，地址需含 /music。账号仍需有相应平台权限，试听和不完整音频会被拒绝。Spotify / YouTube 专有取流服务未内置。站点失败或结果不完整不会直接当作无资源。


### 内置服务与 AI 队列（0.4.5）
安装完整版本后，在连接向导勾选内置 FlareSolverr 和内置 go-music-dl 即可，不需要 Docker 或另填服务地址。引擎按需启动，退出应用及后台时一起停止。已有外部服务的用户可取消“使用程序内置”后保留自定义连接。

在“平台 Cookie / 扫码登录”窗口选择平台，粘贴 Cookie-Editor JSON 或 Cookie 请求头，点击“加密保存 Cookie”；也可生成二维码，用对应手机 App 扫码确认。已保存信息显示圆点，留空不会删除；没有账号可以跳过。扫码过期可刷新，需要额外平台验证时可改用 Cookie。

启用 AI 并保存有效地址、模型和密钥后，匹配失败的专辑会自动加入持久化队列；也可以勾选任务后点击 AI 辅助，或选择全量 AI 核对。系统自行分批，不再只取前 20 项。目录、同一候选比较和曲目映射结果会缓存，正常匹配成功的任务不额外调用 AI。无法确认的项目保留建议和原音源，最后才进入人工核对。普通下载额度的例外授权仍需人工选择。


### 连接与任务恢复（0.4.6）

**连接与设置 → 浏览器验证与内置 FlareSolverr 设置** 可直接打开独立设置页，选择 **使用程序内置 FlareSolverr**，再点 **启动并测试 FlareSolverr**；内置模式无需填写服务地址或程序路径。可在当前页直接 **保存设置**。原有外部服务配置保留，需要内置模式时请明确选择。

任务列表刷新会更新原有任务行，不反复重建整棵列表。**继续勾选** 对暂停任务解除暂停，对具有明确恢复阶段的失败或连接错误任务重新排队；缺少封面、发行选择等人工资料的任务仍需打开核对窗口。旧版遗留的 running 检查点仅在明确点击继续时恢复，并保留下载、令牌与事务对账保护。若整个后台仍暂停，提示会引导点击 **继续整个后台**。

qBittorrent 无法连接时，先确认程序运行、WebUI 已启用、设置中的地址和端口正确；连接错误不表示 PT 站点没有音源。Roon 接口提示需要授权时，请在 Roon 扩展中授权；目录扫描与接口授权分别核对。未知 FL 或下载请求不会因继续而被直接重放。


### 0.4.7 专辑队列与连接测试

任务中心默认打开“专辑总览 / 进行中”，每张专辑显示当前需要处理的阶段；可切换“阶段记录”查看识别和搜索历史。搜索完成只说明检索阶段结束，下载、整理和入库仍需继续。已删除的后续任务不会从完成的前置阶段重新出现。勾选专辑后显示批量操作；切换视图会清空勾选，翻页保留。

后台优先完成下载、整理与入库，避免数千个旧检索任务压住后续处理；下载轮询仍遵守等待时间。旧配置快照只补齐缺省字段，不覆盖原目录或凭据。历史失败任务可勾选重试，FL 与文件事务仍先对账。

打开“连接与设置”，首页点“浏览器验证与内置 FlareSolverr 设置”。测试不会排入音乐处理队列，首次启动最多约两分钟，成功或失败均直接显示；主界面不再单独放置 FlareSolverr 入口。qBittorrent 页面可测试已保存的下载连接，修改地址和账号后先保存；测试只读，不添加下载。

## 0.4.8：统一下载标签与纠正平台资料

新下载的 qBittorrent 标签固定为 `MusicOps`，任务归属继续由本地创建记录、种子哈希、分类和独立目录核实。连接与设置的 qBittorrent 页提供“将已有 MusicOps 任务标签统一为 MusicOps”，可整理历史任务标签及确认未使用的旧标签；其他手动标签和做种保留，不重加种或启动下载。连接失败后可在连接恢复时再次整理。

流媒体平台提供的专辑、歌手不是最终身份依据。普通匹配失败后按歌名＋歌手、仅歌名逐步查找，目录 API 优先，再查网页和 AI。仅同名不能确认为同一录音；完整时长、真实发行曲目表、艺人、现场 / 翻唱 / 混音等版本仍需核对。原始平台字段保留，修正后的资料用于重新搜索，未核实的线索进入核对队列。无 AI 时仍可查目录，不能唯一确定的内容交由用户选择。


## 0.4.9 去重合并与后台资源

在侧栏打开“去重合并”，先扫描，再勾选可靠项目或选择“自动合并全部可靠项”。扫描不会改动主库；只为重复候选进行完整验证，不全库解码。无发行身份时，仅文件字节或完整解码音频相同的重复歌曲自动去重；同一发行的分散曲目可补齐合并，保留较好音源和缺失资料。存在不同版本、声道、CUE、歌词或封面冲突时显示原因，原文件保留。单次最多处理 1,000 组，完成后可再次扫描其余项。

执行时重新核验音频、歌词、封面与 CUE 是否发生变化，旧副本进入隔离区，事务与备份保存在私人档案中。点击“恢复上次合并”可恢复最近一批已提交事务；重启后进入该页会读取最近记录。不要手动清理仍需恢复的隔离区、工作区或备份。合并按专辑事务逐项提交；中途冲突时先前已完成的事务保留，重新进入该页可读取其恢复记录，再扫描未完成部分。

Windows 自动检测系统报告的小核，对 MusicOps 和它启动的组件设置后台优先级；常见单处理器组机器会严格绑定小核，多组机器使用 CPU Sets。未检测到大小核时不猜编号。设置第一页显示调度状态。文件校验最多 4 项并行、界面请求最多 8 项、解码单线程；CPU 让前台优先，磁盘和网络仍会按实际工作量使用。macOS 使用较低进程优先级，具体核心由系统安排。

去重页的“停止当前扫描 / 合并”只停止这一次任务，在当前文件或专辑事务的安全点生效；已完成部分仍可恢复，不会暂停或取消其他专辑下载。


0.4.9 下载与资料补全：选择音乐库后，下载、整理和恢复目录位于同级 MusicOps 文件夹。入库通过完整校验后清理本任务临时副本；PT 原始文件由 qBittorrent 移到永久 seeding 目录继续做种，不要手动清空。资料补全会重新检查旧版只生成旁置歌词的项目，将已核对歌词同时写为同名 .lrc 和 Roon 可导入的歌词标签。没有可靠歌词或封面时明确保留未找到/需核对状态，不把服务失败当作资源不存在。


## 把多个批次放进一张合辑

在“去重合并”点“合并为一张合辑”，输入原专辑关键词，查找并勾选要合并的批次。填写最终专辑名，“合辑分组艺人”默认群星，仅用于整张专辑分组，**每首歌曲原有艺人保持不变**。先生成预览，核对曲数和目标目录后确认合并。原件进入库外隔离区，去重页可恢复最近一批。暂存音频在成功提交后清理；用于做种的文件不允许直接移动。

普通版、现场、重制、豪华或再发行音源并存时，在任务核对页勾选一个或几个需要的版本，每个版本分组选一个站点音源。界面提供年份、目录号与介质作为比较线索，资料不足仍需核对。多选版本分别下载和入库，原版保留；不把曲目内容不同的版本作为音质升级删除原版。

封面会检查库内 cover、folder、front，以及“艺人 - 专辑名.jpg”。同优先级存在不同正面图片时需选择，不会自动以网络图片掩盖冲突。可在补全资料设置选择中文简体偏好；仅转换有中文语言证据的资料，未知语言或日文名称保持原文。
