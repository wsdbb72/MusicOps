# MusicOps 操作指南

Mac 推荐下载对应芯片的 `.pkg`：Apple Silicon 选 `arm64`，Intel 选 `x86_64`。双击后按系统安装向导安装，完成后从“应用程序”打开 MusicOps。ZIP 是保留的手动安装方式。升级前，在“任务中心”点击“退出应用及后台”；正在执行的任务需要完成或取消后再退出。安装器保留用户资料和钥匙串凭据。

[返回首页](../README.md) · [备份与恢复](运维与恢复说明.md)

MusicOps 有五个主要页面：**歌单入库、资料补全、音质升级、任务中心、专辑搜索**。先通过 **连接与设置** 保存运行所需信息，再选择要做的事；前三个工作流的进度和核对事项都在任务中心查看，手动专辑搜索单独显示检索结果。

## 首次配置速查

每一步都可以跳过，已有服务以后还能修改。完整图文结构与填写说明见 [README 的七步配置](../README.md#第一次使用七步配置)。

| 向导步骤 | 必要内容 | 可以跳过的部分 |
| --- | --- | --- |
| 音乐放在哪里 | 选择存放成品音乐的目录 | 暂不使用 Roon 可不勾选 |
| 连接四个资源站 | 有账号的站点：JSON Cookie + 参与检索 | 没有账号的站点关闭 |
| 连接 qBittorrent | 站点下载需要 WebUI 地址、用户名、密码 | 只补全已有文件时可跳过 |
| 网易云回退与媒体工具 | 整理和验证需要 FFmpeg、ffprobe 路径 | API、网易云登录态、客户端下载目录均可选 |
| 歌单平台授权 | 遇到登录要求时，选择对应平台填写 Cookie / Token / API Key | 九个新增平台授权均可跳过，先尝试公开读取或导入文件 |
| 补全封面、歌词与资料 | 使用私人歌词服务时填地址、完整鉴权原文 | Discogs、AI、私人歌词服务可跳过 |
| 连接 Navidrome | 启用时填服务地址、用户名、密码 | 只用 Roon 或暂不接入时跳过 |

保存后可以开始使用。使用 Roon 时，还要在 **Roon → 设置 → 存储** 添加所选音乐库。Navidrome 需要读取同一批文件，远程或容器部署要核对挂载映射。

## 凭据已保存时如何修改

Cookie、密码、接口鉴权、Token 和 API Key 等已保存项，会显示点号 / 星号及保存状态提示。**显示的是状态掩码，不是从保险库取出的真实值。**

- 保留掩码不改动：继续使用原凭据。
- 输入新内容或导入新的 JSON：保存后替换对应凭据。
- 新值留空：保留已保存值，不把空文本当作新凭据。
- 修改服务主机名：旧凭据不会自动转发到新域名，需要重新填写。
- 关闭“参与检索”或某项服务的启用开关：暂停使用该连接，已有保存值仍可保留。

qBittorrent 更新密码时也需要填写对应 WebUI 用户名。歌词接口鉴权填写服务提供的完整 `Authorization` 原文，无需自行加 `Bearer`；服务原文已包含此前缀时完整保留。不同服务的密钥不能互相代替。

### JSON Cookie 导入失败或登录失效

1. 重新打开对应网站，确认浏览器内仍能访问账号页面。
2. 从该站当前页面用 Cookie-Editor 导出 **JSON**，导入到同一站点。
3. 检查它是 `[` 开头的对象数组，不是账号密码、链接或 HTTP 请求头文本。
4. PT 站点确认勾选“参与检索”；歌单授权页选对平台并保存，然后重试。

导入时会检查 Cookie 所属域名；其他站点的 Cookie 不会被当作该站凭据。`已保存`只证明本地存有凭据，无法保证网站登录态尚未过期。请勿把 JSON 内容粘贴到 Issue、聊天记录或公开日志。

### 歌单平台授权填写

PT 下载站点与歌单来源平台的授权分开保存。新增的 **歌单平台授权（可选）** 页提供 QQ、汽水、酷狗、酷我、咪咕、bilibili、Spotify、Apple Music、YouTube 的选项；网易云登录态仍在回退配置页。

国内平台与 bilibili 使用对应域名 Cookie JSON。Spotify 填 OAuth Access Token，Apple 填 Developer JWT，YouTube 填 API Key 或 OAuth Access Token；这些不是账号密码，MusicOps 不自动获取或刷新它们。具体 JSON 写法与平台限制见 [平台与授权指南](references/global-playlists.md)。

## FL 免费下载设置

“最多使用 FL 免费下载”用于 DicMusic / Orpheus / RED，按本批工作流计数：

| 设置 | 行为 |
| --- | --- |
| `0 次 / 批次` | 不使用 FL，只采用已免费的资源 |
| `X 次 / 批次` | 本批最多使用 X 次 FL |
| 勾选“全部” | 次数框变灰并忽略其数值，本批不设次数上限 |

“全部”不改变这三个站点只使用免费路径的规则。程序仍检查站点余额、实际免费状态和种子身份。余额不足、免费状态未知、接口超时或请求结果不明时，任务会等待核对，不自动重复请求。OpenCD 直接获取种子，不消耗这里的 FL 额度。

## 歌单入库

1. 在 **歌单入库** 选择自动识别并粘贴支持平台的歌单链接 / 分享文本；输入纯 ID 时先选择平台，点击 **解析歌单**。
2. 勾选需要入库的曲目；**全选 / 取消** 切换全部可见条目。
3. 点击 **开始入库**。任务中心先显示本次批次准备，再逐步生成专辑任务。
4. 观察后续搜索、下载、资料整理、音频验证与入库进度。

网易云与其他已实现的分页路径不会在本地硬截断为前 1000 首。各平台公开可见范围不同，Spotify 等公开预览不等于全量；上游清单不完整时会警告，仅处理用户明确选择的可见曲目。音乐库中身份、专辑和已知时长匹配的曲目跳过，余下需求按专辑合并。

资源站通常提供整张发行，所选曲目可能带来整张专辑下载。若歌曲或专辑身份不明确，先在任务中心核对，不会用另一首同名歌曲替代。

### 导入歌单文件

点击 **导入文件**，选择 JSON、CSV、TSV、TXT、M3U / M3U8 或普通 XLSX。优先使用保留平台、原 ID、艺人、专辑与时长的 JSON；常见带中英文列名 CSV 也可使用。

TXT 导入时明确选择 **歌名 - 歌手** 或 **歌手 - 歌名**，防止两列反转。没有列名的表格或有歧义的分隔符不会按位置猜测。M3U 只读取 EXTINF，XLSX 只读取普通单元格；不会打开音源路径、执行脚本、宏、公式或外部工作表。带公式的工作簿请另存为纯值 CSV。

单文件 20 MB、50,000 首；UTF-8 / BOM 优先，GB18030 回退会标明。缺少专辑、歌手或时长的文件仍会保留缺失状态；需要补足可靠资料，不能只填“未知”来强行入库。

### 网易云回退的条件

已启用站点均完成检索并没有匹配资源，歌单任务才进入网易云回退。未启用站点跳过；登录、网络、限流或分页不完整的问题先等待处理。

回退支持直接获取完整可用音源，也可以接入已经下载好的客户端文件。可选 API 服务需要提供 `/song/url` 响应，自定义 API 的账户权限由该服务负责。API 不可用或网易云只有试听、无完整下载权限时，保留具体原因，不保证所有歌单曲目都能获取。

其他平台的 ID 不会被当作网易云 ID。跨平台回退前必须得到唯一的网易云歌曲引用，歌名、艺人、专辑和完整时长都要匹配；缺少可靠资料或存在多个候选时等待核对。视频频道与 UP 主不自动作为音乐歌手。

接入客户端下载目录时，按照歌曲、艺人、专辑资料匹配。多个相同曲目版本无法唯一判断时需要处理冲突。NCM 在工作副本中解密；原 NCM 不变，做种源不变。过大的导入目录可改选具体专辑子目录。

## 资料补全

点击 **检查并自动补全** 后，检查已有音源的歌曲、艺人、专辑、专辑艺人、封面、同步 `.lrc` 和多碟编号等资料。可靠证据可以自动补齐；资料冲突、曲序缺失和被锁定字段会转为待核对。

封面与歌词可能确实没有可靠来源。界面会区分“暂无匹配资料”和鉴权、网络失败；后者需要先处理连接。无歌词不等于音频损坏。选择跳过某次资源服务时，仅按该次确认继续。

暂无资料的结果会短期缓存，避免反复访问同一服务。需要立即重新查询时，点击 **重新查询暂无资料**。

同步歌词与音频同名，例如 `01 - Song.flac` 对应 `01 - Song.lrc`。多碟专辑会核对碟号与总碟数；不能把不同录音或不同发行仅按同名合成一张专辑。

## 音质升级

点击 **检查并自动升级** 后，先识别现有音源，再从已启用站点寻找候选。站点给出的格式和音质信息用于筛选，下载后还会检查实际媒体信息、曲目完整性、时长和解码结果。

对于同一录音与发行：有损同编码音源可比较有效码率，无损音源比较位深和采样率；不同声道和身份不明的候选不会自动替换。高码率无损文件未必更好，24 bit 也不代表一定来自更好的母带。

新版完整验证并成功入库后，旧版才移出音乐库监听目录，保留恢复内容。缺少同一发行 ID 时，先在任务中心核对版本。程序不会因候选文件名写着“Hi-Res”就删除现有版本。

## 手动专辑搜索

在第五个页面 **专辑搜索** 输入艺人或专辑关键词：

- **原样搜索**：保留输入文本，向已启用的四个资源网站发起检索。
- **识别专辑后精准搜索**：先从 MusicBrainz / Discogs 选择确认的发行，再用标准艺人和专辑名称搜索，并过滤名称或艺人不匹配的结果。

看到多个发行版本时，先核对版本再选择。结果会显示站点、音质和做种数量，以及每个站点本次检索的状态。列表展示接口当前返回页，更多资源可点击 **打开选中资源详情** 继续核对；此页面不自动下载，搜索成功也不等于已建立入库任务。

## 任务中心的操作

| 操作 | 作用 |
| --- | --- |
| 选择任务 | 查看该任务当前步骤、结果与需要处理的信息 |
| 暂停 / 继续 | 暂停或恢复 MusicOps 后续处理，在安全检查点生效 |
| 取消选中任务 | 停止该任务后续处理，已发布内容和做种保留 |
| 核对 / 重试选中任务 | 按提示确认候选、发行、曲序、资料、封面或修复后的连接 |
| AI 解释选中问题 | 可选，用已配置的 AI 辅助解释提示 |
| 恢复选中任务的原版 | 检查恢复内容和当前文件后，回退该任务的文件替换 |
| 上一页 / 下一页 | 浏览分页任务，避免大批量任务拖慢界面 |

**批次准备**也会作为任务显示，在扫描与创建专辑任务期间报告阶段和已检查数量。若没有生成专辑任务，请先查看该批次的结果：全部需求已满足、近期资料检查缓存命中和真正创建失败含义不同。

从旧版更新后，之前尚未完成的准备请求会保留为“上次准备任务”记录，提示重新开始；多次点击积累的旧请求不会自动执行下载。返回对应入口，检查歌单选择和设置后重新开始即可。准备记录本身没有文件替换可恢复，恢复时应选择具体专辑任务。

需要核对的任务会等待选择，不是持续后台重试。FL 结果不明、qBittorrent 新增或启动状态不明时，先查看站点和下载器实际状态，避免重复操作。中断的文件事务会保留记录，恢复前仍会检查文件一致性。

关闭窗口后，后台继续；重新打开相同档案即可查看。换一个 `profile` 会看到另一套任务和设置。暂停或取消不会自动停止 qBittorrent 做种，也不会回滚已完成发布。

## 遇到问题时

先看 [README 的状态与处理表](../README.md#任务中心与常见问题)。反馈时提供版本、操作入口、脱敏后的完整提示，以及问题发生在扫描、下载、整理还是入库阶段。不要发送整个私人运行档案。

音乐服务器未显示新文件时，确认文件已实际入库、服务器能读取相同目录、扫描已经结束，再在客户端搜索并播放。MusicOps 报告扫描请求成功不能代替客户端可见性与播放检查。

备份、更新、恢复与工作目录说明见 [运行档案与恢复](运维与恢复说明.md)。
