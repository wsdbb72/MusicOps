# 运行档案、更新与恢复

对应 **MusicOps 0.4.3**。更新程序只替换应用运行文件；私人运行档案和恢复内容需要继续保留。

[返回首页](../README.md) · [操作指南](用户操作说明.md)

## 先分清三种目录

| 目录 | 保存什么 | 谁来读取 |
| --- | --- | --- |
| 应用目录 | EXE、`_internal`、许可证等运行文件 | Windows / MusicOps |
| 运行档案 `profile` | 配置、SQLite 状态、凭据、任务、下载与恢复内容 | MusicOps；属于私人数据 |
| 选定音乐库 | 完成整理并通过检查的音乐及同名歌词 | Roon / Navidrome |

让音乐服务器只读取成品音乐库。下载、工作、备份和隔离目录留在监听范围外；不要让音乐服务器监听整个盘符或音乐库的上级目录。

每个运行档案拥有独立的设置和任务。GUI 与后台必须使用相同档案。

| 系统 | 默认档案与更新关系 |
| --- | --- |
| Windows 安装版 | 快捷方式显式选择安装目录下的 `profile`，更新保留 |
| Windows 绿色版 | 优先有效的随包 / 已记住档案；否则使用本地应用数据目录 |
| macOS | `~/Library/Application Support/MusicOps/profile`，位于 `.app` 外；替换应用不覆盖档案 |

Windows 绿色版可用以下命令固定档案：

```powershell
.\MusicOps.exe --base .\profile
```

不指定 `--base` 时，程序按当前系统规则选择档案。macOS 不采用应用包内部的相邻 `profile`，避免把私人状态写入签名的 `.app`。突然看到空任务、不同设置时，先检查是否打开了另一个档案。

## 如何备份

1. 等待当前文件操作完成，暂停后续工作；需要长期停止的任务可取消，并等待界面确认。
2. 关闭该档案的桌面窗口，并确认其后台已经停止。**关闭窗口本身不会退出后台。**
3. 复制完整运行档案到独立备份位置。不要只复制 SQLite 主文件，或漏掉可能存在的伴随文件。
4. 音乐文件本身、外部媒体工具，以及音乐库上级的 `.MusicOps-work-…` 工作区要按需要分别备份。

Windows 的 `profile/vault` 秘密值由当前账户 DPAPI 保护。macOS 使用登录钥匙串保存主密钥，本地 `secrets.keychain` 为 AES-GCM 加密文件；钥匙串不可用时会报错，不回退为明文。完整档案可以用于原账户与原系统凭据仍可用时的状态恢复；复制到另一台机器、账户或系统后，不保证凭据还能解密。迁移时保留状态和音乐，准备重新填写服务凭据。

已完成的音质替换若仍需要可回退，务必保留 `backup`、`quarantine` 和对应事务记录。**备份档案不等于备份全部音乐。**

## 如何更新应用

默认自动检查 GitHub 最新正式版、下载当前系统安装器并校验 SHA-256。后台活动步骤完成并安全退出后，Windows 延迟交接程序等待 GUI 与 worker 释放文件，再次校验后启动安装器；Mac 打开 ARM PKG 原生向导。安装仍需按系统提示完成，不跳过管理员授权或系统安全检查。侧栏“检查更新”可手动重试，设置向导可关闭自动更新。更新缓存保存在系统用户数据目录的 `MusicOps/updates`，与音乐库分离。

手动更新：

1. 从 [最新 Release](https://github.com/wsdbb72/MusicOps/releases/latest) 下载 Windows `Setup.exe` 或匹配芯片的 Mac `.pkg`，按需要核对 SHA256。0.4.3 对应 `MusicOps-0.4.3-Setup.exe`、`MusicOps-0.4.3-macOS-arm64.pkg`。
2. 保留完整旧档案与原版本。在任务中心点击 **退出应用及后台**；若还有活动任务，等待完成，或自行取消后等到安全阶段再退出。**暂停和关闭窗口都不能证明后台已退出。** 安装器不会强制结束应用或取消任务。
3. Windows 运行安装包，先核对“更新 MusicOps”中显示的原目录。安装器会优先使用已检测到的旧版，更新运行文件并保留 `profile`、凭据、任务和 `tools`；没有检测到旧版才进行新安装。它会拦截已知的降级安装及把已登记安装改装到另一目录的操作。
4. 以前使用绿色版且没有被自动识别时，在目录页选择原来的完整 MusicOps 文件夹；安装器会识别该目录为更新。程序只检查常见位置和已有安装记录，不会扫描所有硬盘来猜目录。若仍使用 ZIP 手动更新，应替换同版本的完整运行文件，保留私人档案、工具及音乐。
5. Mac 双击对应 `.pkg`，更新 `/Applications/MusicOps.app`；选择 ZIP 时替换完整应用。两种方式都保留用户目录中的档案和钥匙串凭据。安装器发现应用或后台仍在运行时会阻止替换，先退出后重试。
6. 打开新版本，确认版本、音乐库、连接保存状态和任务历史正确，再继续任务。原来需要核对的发行仍需核对，不会因升级自动确认。

Windows 的 `MusicOps.exe`、`MusicOps-worker.exe`、`_internal` 应来自同一版本；macOS 保留 `.app` 的完整结构。文件正在使用时，先处理后台进程，避免覆盖一半形成混合版本。不要把开发源码、测试报告或第二套后台文件复制进运行目录。

安装器保留私人 `profile`，卸载时也不会主动删除它。保留不等于另有备份；重要资料仍应独立备份。

### macOS 首次打开与校验

下载 `arm64`（Apple Silicon）包；0.4.3 起停止构建 Intel，历史附件保留，目标系统为 macOS 15 及以上。解压后运行 `MusicOps.app`，无需 Python。可在终端对实际 ZIP 运行 `shasum -a 256 "文件名.zip"`，与同一 Release 的对应 `.sha256` 核对。

当前没有 Developer ID 签名或 Apple 公证，仅有 ad-hoc 完整性签名。系统拦截时，确认来源与校验值后按 **系统设置 → 隐私与安全 → 仍要打开** 操作，参见 [Apple 官方说明](https://support.apple.com/en-us/102445)。无需关闭 Gatekeeper 等系统保护。macOS 构建与包内自检依赖 GitHub Actions 的对应架构任务；源码或静态检查通过不能代替该任务成功。

## 为什么有工作副本和恢复目录

下载和整理目录位于音乐库同级的 `MusicOps` 文件夹，例如 `E:/music` 对应 `E:/MusicOps/downloads`、`work`、`seeding`、`backup`、`quarantine`。程序在工作副本上处理标签、封面、歌词、NCM 解密与完整解码检查。入库文件逐项校验成功后才删除有任务清单和哈希记录的临时文件；外部客户端下载原件不会被自动删除。

PT 原始文件不能补写标签，否则会改变种子校验。发布成功后，MusicOps 请求 qBittorrent 把原始文件从临时目录迁移到永久 `seeding/任务ID`，同时调整该种子的保存和临时路径，保存迁移检查点并核对文件字节。文件迁移中、路径不符、目标冲突或校验失败时保留现场并等待核对，不会删除种子或重新加种。音乐库保存整理后的独立副本；`seeding` 中的音频是持续做种所需原件。

同步歌词保存为同名 UTF-8 `.lrc`，已核对歌词还会补写到入库副本的歌词标签供 Roon 导入。Roon 官方支持标签导入歌词；实际歌词显示和同步状态需在 Roon 中确认，不能把旁置文件存在当作显示验收通过。旧版仅生成旁置歌词的资源缓存会在新版本重新检查。

新发行通过检查后才提交入库。资料补全的原文件和音质升级的旧版会按文件事务记录保留在恢复位置。程序不会因为配置中存在某个保留天数字段，就自动定期清理这些恢复内容。

| 内容 | 清理前需要确认 |
| --- | --- |
| `downloads` 临时下载目录 | 是否还有未完成或待核对任务；旧版 `profile/source` 先核对客户端归属和实际路径 |
| `seeding` 永久做种目录 | qBittorrent 是否仍引用；不能直接清空 |
| `work` 与旧版 `.MusicOps-work-…` | 是否存在下载、待核对或中断任务，是否需要恢复 |
| `backup` / `quarantine` | 新版是否可用，是否不再需要回退历史 |
| `state` / `vault` | 属于运行状态与凭据，不能当作缓存删除 |

清理会减少可恢复的历史。不要仅凭目录名或文件时间，批量删除所有旧内容。

## 恢复某次资料修改或音质替换

1. 打开 **任务中心**，选择需要恢复的任务。
2. 如果仍在处理，先取消并等待进入安全终态。
3. 点击 **恢复当前任务原版**，阅读确认提示；恢复作用于当前任务，不是全部勾选项。
4. 程序核对当前文件、恢复副本和事务记录，再恢复原版并移出本任务的新文件。
5. 在 Roon / Navidrome 中等待或触发重新扫描，确认结果。

恢复不会停止做种，不会直接接管无关下载。若文件后来被其他标签工具修改、目标路径冲突、恢复副本丢失或事务不一致，恢复会拦截并留下原因。此时保留文件和日志，核对冲突，不要直接改数据库或覆盖文件来绕过检查。

没有发生文件修改的任务无需恢复。取消与恢复也不同：取消只停止后续处理，已完成的文件提交不会因为取消而自动撤销。

## 中断、扫描和状态异常

### 批次准备耗时

大音乐库需要读取目录和标签。任务中心的准备任务会显示扫描阶段、**已检查的本地音频文件数**、缓存复用数和错误；歌单选择数另列。这一步先建立本地索引，随后识别缺失需求并创建搜索任务。例如歌单 4,080 首、本地库 10,000 个音频文件，扫描数超过歌单数不代表歌单被扩大。没有新专辑任务时，要区分需求已满足、资料缓存命中和真正失败。

旧版尚未完成的准备请求在更新后会停止自动执行，并显示为需要重新开始的历史记录。这样可以避免旧版多次点击排队的请求在升级后重复下载。按提示返回对应入口重新开始，不要改写旧记录强行恢复执行。

旧版扫描已结束、但缺少批次准备记录的专辑队列也会进入“需要核对”，升级时不会自动重放。原来的处理阶段、已有下载、做种、令牌和事务记录保留。确认任务与当前音乐库相符后，可以手动继续对应专辑；若是重复点击形成的旧队列，返回工作流重新开始即可。

扫描时发现文件变化，索引会重试一次；仍在变化的文件会记录为忙碌，需要稍后复查。扫描和快速索引不会代替入库前的完整解码验证。

### 如何批量停下或继续任务

任务中心分为 **识别任务、搜索任务、下载与入库**，展开可看专辑与曲目。勾选任务后使用 **暂停勾选、继续勾选、取消勾选**，每批最多 500 项。翻页保留勾选；“勾选本页”与分类勾选只作用于当前页。操作结果会分别统计已处理、跳过与未找到的任务。

批量暂停在当前阶段结束后生效，取消停止后续步骤；两者都不自动回滚已入库文件或停止 qBittorrent 做种。准备批次可以控制关联的未完成任务。需要核对的任务、已结束的任务不会通过批量继续强行重跑；应点击具体任务使用 **核对当前专辑**。**暂停整个后台**控制全队列，与勾选暂停分开。

AI 辅助一次处理前 20 项，基于真实目录或已观察到的候选生成可编辑建议；在核对窗口检查并采用后才继续。需要回退文件替换时，使用当前任务的恢复操作并核对事务，不要把取消当作恢复。

### 站点报错与 AI 识别

资源站独立返回结果。正常没有资源属于成功检索；Cookie 失效、限流和网络失败显示具体站名与原因，其他站点继续。可用站点无匹配时，开启网易云回退的歌单任务可以继续回退；全部已启用站点都不可用时才等待检查连接。某站失败不等于全部站点没有资源，也不会清空其他站的候选。

配置并启用 AI 后，常规识别无唯一可靠匹配时会自动尝试别名检索，并从实际目录候选中推荐；必要时用规范名称再查资源站。AI 异常保留普通结果，模型输出也不能代替本机的发行、曲目、时长与音频验证。AllMusic 等人工官网入口仍需用户查证，未新增自动抓取。遇到多版本、缺少完整时长或不一致资料，保留待核对状态并按界面处理。

### 网络或 FL 请求中断

先核对站点和 qBittorrent 的实际状态，再决定继续。免费请求超时可能已经在服务端生效；MusicOps 保留未知状态，不盲目重复请求。暂停 / 取消在安全检查点生效，正在进行的单个网络请求可能要先返回。

### 文件操作中断

保留原音源、恢复目录与事务记录。重启后需要核对的任务会提示中断，按界面说明处理。文件冲突不会通过重启自动消失，不能用删除 SQLite 或手改事务状态来强行入库。

### 音乐服务器未发现文件

先确认任务确实已入库，再检查音乐服务器监听的目录、权限与容器映射。Navidrome 扫描请求成功只表示请求被接受，Roon 的历史日志也不能替代当前客户端里的曲目可见性检查。到客户端搜索和播放后再确认结果。

## 开发者的后台检查

源码环境可通过 CLI 查看状态，`--base` 必须填实际运行档案的完整路径。例如在仓库根目录，把下列占位路径替换后运行：

```powershell
.\.venv\Scripts\musicops.exe --base "C:\MusicOpsProfile" get_status
.\.venv\Scripts\musicops.exe --base "C:\MusicOpsProfile" shutdown_worker
```

安全退出请求只在后台没有活动任务时通过。不要把它改为强制覆盖状态；应先完成或安全取消任务。CLI 输出可能含个人目录、服务地址和音乐资料，仅在本地查看，公开反馈前脱敏。

## 反馈与隐私

反馈时附上应用版本、操作入口、脱敏的错误文字和复现步骤即可。不要上传完整运行档案、数据库、Cookie JSON、鉴权文件、账号截图或包含下载密钥的种子链接。

源码中的合成测试验证的是指定场景。真实站点规则、账号权限、音源文件和音乐服务器显示仍取决于现场环境。

## 删除、重试和本地索引的保留

任务删除使用隐藏标记，并取消关联后续处理；不删除音乐、种子、做种或文件事务。底层恢复与审计证据保留。失败任务可单项或批量重试，使用当前连接设置并沿用原下载归属与 FL 账本；未知事务或人工资料问题会保留明确的核对要求。

本地专辑资料库保存在同一个私人 SQLite 数据库，`library_albums` 保存专辑归组，`library_matches` 以规范化歌曲 / 艺人 / 专辑和时长建立查询索引。扫描时增量读取变动音频，未改变的专辑映射可复用。库目录变化使用独立索引键，不混用旧目录。索引可由“更新本地资料库”重新建立，不是音频备份，也不替代完整解码验证。


## 0.4.4 任务与完整专辑补充

DicMusic / Orpheus 默认只走 FL 令牌或已确认个人免费路径。令牌不足时弹窗等待；普通下载必须在该弹窗明确授权一次或当前批次，可能计入下载量，不能由 AI 或重试操作暗中启用。旧未知请求先对账，切勿删除数据库强行重试。

0.4.5 修复旧缓存仅证明当时免费而无法继续 FL 的情况。重试先查当前个人免费状态；未生效时核验实时 FL 按钮、余额与额度，重新带 `usetoken=1` 请求。旧请求归档，已确认消费保留并继续计入所属批次；新请求仍使用原子预留防止并发重复消费。结果未知时不允许重新使用令牌，先通过同一种子的个人免费状态对账。无需清空缓存或删除账本。

任务中心可分类筛选、全量失败重试、全量 AI 核对及连续手动核对。手动保存成功后进入下一张，关闭窗口不保存。整专辑补全先取得完整发行曲目表，再只发布缺曲，不覆盖原音源。

其他流媒体回退通过可选 go-music-dl Web 服务接入，地址含 /music；凭据在向导填写并加密。账号权限在服务侧提供，试听与不完整音频会被拒绝。Spotify / YouTube 的专有音源服务未内置。站点失败或结果不完整时不会自动判为无资源回退。详细配置和支持边界见中文 README。


### 连接与任务恢复（0.4.6）

**连接与设置 → 浏览器验证与内置 FlareSolverr 设置** 可直接打开独立设置页，选择 **使用程序内置 FlareSolverr**，再点 **启动并测试 FlareSolverr**；内置模式无需填写服务地址或程序路径。可在当前页直接 **保存设置**。原有外部服务配置保留，需要内置模式时请明确选择。

任务列表刷新会更新原有任务行，不反复重建整棵列表。**继续勾选** 对暂停任务解除暂停，对具有明确恢复阶段的失败或连接错误任务重新排队；缺少封面、发行选择等人工资料的任务仍需打开核对窗口。旧版遗留的 running 检查点仅在明确点击继续时恢复，并保留下载、令牌与事务对账保护。若整个后台仍暂停，提示会引导点击 **继续整个后台**。

qBittorrent 无法连接时，先确认程序运行、WebUI 已启用、设置中的地址和端口正确；连接错误不表示 PT 站点没有音源。Roon 接口提示需要授权时，请在 Roon 扩展中授权；目录扫描与接口授权分别核对。未知 FL 或下载请求不会因继续而被直接重放。


### 0.4.7 专辑队列与连接测试

任务中心默认打开“专辑总览 / 进行中”，每张专辑显示当前需要处理的阶段；可切换“阶段记录”查看识别和搜索历史。搜索完成只说明检索阶段结束，下载、整理和入库仍需继续。已删除的后续任务不会从完成的前置阶段重新出现。勾选专辑后显示批量操作；切换视图会清空勾选，翻页保留。

后台优先完成下载、整理与入库，避免数千个旧检索任务压住后续处理；下载轮询仍遵守等待时间。旧配置快照只补齐缺省字段，不覆盖原目录或凭据。历史失败任务可勾选重试，FL 与文件事务仍先对账。

打开“连接与设置”，首页点“浏览器验证与内置 FlareSolverr 设置”。测试不会排入音乐处理队列，首次启动最多约两分钟，成功或失败均直接显示；主界面不再单独放置 FlareSolverr 入口。qBittorrent 页面可测试已保存的下载连接，修改地址和账号后先保存；测试只读，不添加下载。

## 0.4.8：统一下载标签与纠正平台资料

新下载的 qBittorrent 标签固定为 `MusicOps`，任务归属继续由本地创建记录、种子哈希、分类和独立目录核实。连接与设置的 qBittorrent 页提供“将已有 MusicOps 任务标签统一为 MusicOps”，可整理历史任务标签及确认未使用的旧标签；其他手动标签和做种保留，不重加种或启动下载。连接失败后可在连接恢复时再次整理。

流媒体平台提供的专辑、歌手不是最终身份依据。普通匹配失败后按歌名＋歌手、仅歌名逐步查找，目录 API 优先，再查网页和 AI。仅同名不能确认为同一录音；完整时长、真实发行曲目表、艺人、现场 / 翻唱 / 混音等版本仍需核对。原始平台字段保留，修正后的资料用于重新搜索，未核实的线索进入核对队列。无 AI 时仍可查目录，不能唯一确定的内容交由用户选择。


## 0.4.9 去重合并与后台资源

在侧栏打开“去重合并”，先扫描，再勾选可靠项目或选择“自动合并全部可靠项”。扫描不会改动主库；只为重复候选进行完整验证，不全库解码。无发行身份时，仅文件字节或完整解码音频相同的重复歌曲自动去重；同一发行的分散曲目可补齐合并，保留较好音源和缺失资料。存在不同版本、声道、CUE、歌词或封面冲突时显示原因，原文件保留。单次最多处理 1,000 组，完成后可再次扫描其余项。

执行时重新核验音频、歌词、封面与 CUE 是否发生变化，旧副本进入隔离区，事务与备份保存在私人档案中。点击“恢复上次合并”可恢复最近一批已提交事务；重启后进入该页会读取最近记录。不要手动清理仍需恢复的隔离区、工作区或备份。合并按专辑事务逐项提交；中途冲突时先前已完成的事务保留，重新进入该页可读取其恢复记录，再扫描未完成部分。

Windows 自动检测系统报告的小核，对 MusicOps 和它启动的组件设置后台优先级；常见单处理器组机器会严格绑定小核，多组机器使用 CPU Sets。未检测到大小核时不猜编号。设置第一页显示调度状态。文件校验最多 4 项并行、界面请求最多 8 项、解码单线程；CPU 让前台优先，磁盘和网络仍会按实际工作量使用。macOS 使用较低进程优先级，具体核心由系统安排。


## 0.4.22：恢复资料补全任务

在任务中心勾选曲序、封面或歌词待核对任务，选择“重试选中失败任务”，会保留已准备的副本，改用当前保存的接口与登录设置重新补全；缺少可靠证据时仍回到核对队列。先在设置中测试歌词接口，鉴权失败不会被自动当作没有歌词。网络临时失败会在 60／120 秒后重试，最多两次；无需连续点击。

已有文件事务或音乐目录变化时，不会重新修改事务占用的副本，应先恢复或核对事务。Linux 原有长路径保持不改名；路径逃逸、软链接及文件系统长度限制继续检查。原始文件真正解码失败时，保留它和校验说明，需要核实其他已有副本或取得完整音源，不能靠修改曲号、补封面或跳过校验修复音频。
