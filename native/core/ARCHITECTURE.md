# Go 核心迁移契约

目标是一个 Go 后端、一套业务状态与任务执行路径，桌面和服务器共用 Web 操作界面。现有 Python 只在模块尚未替换时继续承担原功能；替代经过同等业务验证后删除旧入口。SQLite 只由独立、只读迁移工具读取，不提供 SQL 到 KV 的兼容执行层。

当前正式程序仍是 0.4.31；这个开发分支尚未接管生产数据，不能拿数据服务启动成功当作整个 MusicOps 重构完成。

## 已实现的任务边界

- Pebble 的原子条件批写只负责读条件和同步 WAL；业务请求回执由 Repository 与其状态变化一起提交，不重复维护第二套底层请求日志。
- 参数与结果按内容压缩寻址，任务头、队列、最近任务索引和状态计数不包含执行清单。结果保留到对应执行尝试，重试不会抹去上一轮结果。
- 一次领取只有一个启动身份 owner 和递增 fence。先领取，再 Begin，才允许执行外部动作。Begin 前取消可以立即结束；已经开始的操作在检查点确认暂停或取消。
- 单个阶段完成与一个或多个后继任务的创建已合并成同一个条件批写，包含参数、父子索引、状态计数和回执；后继碰撞会阻止父阶段完成，响应丢失后不会重复派生。已有取消请求时不创建后继，已有暂停请求时后继保持暂停。
- 进度采用 owner/fence/sequence 去重；重复轮询不持久保存请求回执，取消/暂停标记不会被旧进度覆盖。执行器对相同进度不反复写盘，变化进度节流；阶段改变和控制确认立即保存。
- 任务结束使用当前记录校验 owner/fence，不要求调用方仍持有早于所有进度更新的整行版本。旧执行者不能完成重试后的任务。
- 退出超时只返回“执行未退出”。在已拥有的工作真正返回之前，不释放它的状态或把任务交给新执行者。
- 原生格式2拒绝开发原型格式1，不添加无人使用的原型兼容分支；真实历史来源仍是正式 SQLite 档案。

## 必须原子完成的业务动作

工作流作业的当前阶段、领域证据、活动任务完成和后继队列边已经在**同一个条件批写**里提交，并共用原来的任务回执。不能先写“识别完成”，再单独创建搜索或处理任务。重启或响应丢失后，用同一个请求 ID 取回原回执，不会创建第二批后继。任务队列的领取成功不等于 PT、识别、文件或下载业务已经迁移。

已实现的边只有这些：

- 识别或快照作业完成时创建独立搜索作业，搜索作业完成时创建处理作业。
- 同一作业从资料整理推进到验证、发布或下载前阶段。这些边只记帐，没有执行器去访问站点、文件或下载器。
- 终止为完成、失败、待核对、取消或跳过。缺少执行器时记为待核对，不创建后继。
- 根作业或活动任务已取消时，本次提交不创建后继作业或任务。已暂停时，后继作业和任务保持暂停。
- 通用的任务完成、控制、中断不能改写带工作流归属的任务。领取、Begin、进度和未开始前释放领取仍只更新执行状态。

歌单来源曲目按唯一来源 ID 计数，并保存该集合的摘要；本地文件数和已核对命中数分开保存，不能互相推导。API、网站和目录证据只有在曲目表已核对时才能确认身份。AI 结果和日文/中文别名只作为证据留下，不能单独确认身份，也不能因此创建搜索。合成证据不能标成生产已验证。

`prepare_batch`、`identify_release`、`snapshot_album`、`search_release`、`repair_album`、`process_release`、`publish_album` 只是持久命令名。数据服务不注册它们的执行器；没有执行器时任务保持不可成功完成。工作流失败后的重试、已有兄弟作业的批量暂停，以及媒体、PT、文件和下载执行，仍不属于本切片。

## 文件与下载副作用

队列的 started 标记只证明执行器开始，不能证明下载、FL 消费或文件发布成功。未知结果进入自动对账流程，不因经过若干分钟就释放执行权。

文件事务需要持久意图、私有暂存、完整验证、最终库同盘原子发布、做种迁移确认、拥有范围内清理和保留回滚备份。暂停点不持有数据库快照/事务；handler 返回前必须收回它启动的子工作。未实现并测试这些领域约束前，不注册真实发布/下载 handler。

FL 预约、个人免费状态和种子请求分开记账；结果未知时先只读对账。账号、费用和版本选择的明确授权边界继续保留。任务恢复不等于自动允许收费下载。

## 迁移与删除旧代码的顺序

1. 任务与工作流阶段的原子衔接已经落地。下一步是媒体目录、配置、文件事务和下载账本的明确接口；在这些接口被实现并测试前，不注册对应执行器。
2. 独立工具只读读取 SQLite v1/v2，在隔离 native 目录转换；保留原始记录、凭据引用、历史结果与恢复清单，逐表计数和逐条哈希核验，支持断点重入。
3. 用已有领域测试向量验证端到端行为。三平台运行真实产物，不能用交叉编译代替原生安装验收。
4. 全部必需接口和数据核验通过后，切换唯一后端，删除旧 SQL 业务与重复入口。迁移失败保持旧档案和正在运行的正式版，不隐式清空历史。

原型数据、合成音频和测试凭据只能出现在隔离测试中，不进入正式 profile 或发行资产。
